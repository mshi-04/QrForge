# QrForge サブエージェント運用ガイドライン

サブエージェントは、複数レイヤーやレビュー観点を分けたいときだけ使う。最終判断と差分統合は親エージェントが行う。

## 使う場面

- Rust core、JNI bridge、Kotlin wrapper、sample app の複数レイヤーにまたがる変更。
- 対象範囲、やらないこと、完了条件の整理。
- 実装後レビュー、テスト不足、CI 失敗調査。
- PR 前の変更概要、確認コマンド、残るリスクの整理。

## 使わない場面

- typo 修正。
- 文言だけの小さな修正。
- 1 ファイル内で完結する軽微な変更。
- 親エージェントだけで責務境界と確認結果を判断できる場合。

## 分担ルール

- 依頼時に対象レイヤ、変更してよいファイル、触らない範囲を明示する。
- Rust core と JNI bridge、Kotlin wrapper と sample app の責務を混ぜない。
- 同じファイルを複数担当で同時に編集させない。
- 結果は `docs/architecture.md`、`docs/review-rules.md` と照合してから採用する。
- 実行していない確認コマンドを「通った」と書かない。

## 報告

進捗報告や結果統合では、可能な限り割り当てられた表示ニックネームで呼ぶ。ニックネームがない場合だけ generic な役割名を使う。

最終報告には、変更ファイル、確認コマンド、未実施項目、残るリスクを含める。
